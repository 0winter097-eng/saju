# 사주 계산 기준서

작성일: 2026-09-09  
엔진: 0.1.1 / 규칙: KR-REVIEW-1 / 해석: BASIC-RELATION-1  
상태: 개발 구현 기준. 명리 전문가의 승인 상태는 확인되지 않았으며 정식 확정본으로 취급하지 않음.

## 1. 정확도의 범위

계산 정확도는 이 문서에 정의한 알고리즘과 입력 조건에 대한 재현성을 뜻한다. 해석의 전문가 합의, 경험적 예측 타당성과는 별개다. 정확도·운세·재물·건강에 임의의 백분율을 부여하지 않는다.

## 2. 입력 및 지원 범위

양력 환산 후 1970-01-01~2050-12-31의 대한민국 출생만 지원한다. 실제 출생일, 당시 기록된 현지 시각, 평달·윤달 구분, 도시/경도, 시간 근거, 대운 계산용 성별을 입력한다. 이름·연락처·주민등록번호는 수집하지 않는다.

음력 입력은 한국 음력 기준이다. 해외 음력 체계를 자동 추정하지 않는다. 윤달 미상은 확정 계산을 막고 확인을 요청한다. 출생시간 범위는 같은 현지 날짜 내에서 시작~종료 시·분으로 받는다. 자정 횡단 범위는 날짜별로 나누어 비교해야 한다.

## 3. 시간 처리

- `Asia/Seoul` 규칙 중 1970–2050년 부분을 IANA tzdb 2025b에서 고정했다.
- 표준 UTC 오프셋은 +09:00이며, 1987·1988년 서머타임 기간은 +10:00으로 기록 시각을 절대 시각에 대응한다.
- 1987-05-10 02:00~02:59, 1988-05-08 02:00~02:59 현지 시각은 존재하지 않는다.
- 1987-10-11 02:00~02:59, 1988-10-09 02:00~02:59는 두 번 존재하므로 양쪽 절대 시각을 비교한다.
- 일·시주 표준시 계산에서는 서머타임을 제거한다. 연·월주에는 태양시 보정을 적용하지 않고 절대 시각과 절입을 비교한다.
- 지방평균태양시 선택 시 `UTC + 경도×4분`을 사용한다. 도시 경도는 중심부의 근삿값이며 정확한 출생 건물 좌표가 아니다.
- 균시차를 포함하는 진태양시는 제공하지 않는다. 지방평균태양시를 진태양시라고 표현하지 않는다.
- 조회 기간은 국내 표준시 UTC+09:00으로 고정한다. 현재 거주지·이동·해외 현지 날짜는 반영하지 않는다.
- 미래 시간대 변경이 발표되면 규칙 버전을 올리고 회귀 검증해야 한다.

## 4. 연주·월주·일주·시주

| ID | 규칙 | 주의 |
|---|---|---|
| Y-1 | 입춘(태양 겉보기 황경 315°) 전후에 연주 변경 | 설날·1월 1일 기준과 구분 |
| M-1 | 입춘·경칩·청명·입하·망종·소서·입추·백로·한로·입동·대설·소한 12절에 월주 변경 | 24절기 전부에서 월주가 바뀌지 않음 |
| M-2 | 해당 사주 연간으로 인월 천간을 정하고 월 순서에 따라 순환 | 음력 월간지를 사주 월주로 복사하지 않음 |
| D-1 | 2000-01-07 양력 갑자일을 기준으로 보정된 날짜 차이를 60갑자 순환 | 전체 일진을 KLC 테이블과 교차 대조 |
| D-2 | 기본 00:00 일주 변경, 대안 23:00 일주 변경 | 23:00 선택 시 시주 계산의 일간도 함께 변경 |
| H-1 | 자시 23:00~00:59, 이후 2시간 단위 지지와 일간 기반 시간 | 야자시·조자시의 다른 혼합 규칙은 미지원 |

절기표: Astronomy Engine 2.1.19의 `SearchSunLongitude`로 1969–2051년 24절기 생성. 주변 연도는 범위 끝의 앞·뒤 절입을 찾기 위한 버퍼이다. 시각을 ISO UTC로 저장하고 계산은 밀리초 값으로 비교한다. 출력 UI는 분 단위로 줄이므로 같은 분에 서로 다른 구간 경계가 표시될 수 있다. 결과 JSON에는 원값이 있다.

**계산 시각의 자릿수는 실제 정확도 보증이 아니다.** 공개 라이브러리의 위치 정확도 설명을 절입 초 단위 정확도라고 해석하지 않는다. USNO 2026년 춘분·하지·추분·동지의 공개 분 단위 값을 2분 허용 기준으로 대조했다. 나머지 연도·12절 전체를 공식 역서와 대조한 것은 아니다.

## 5. 입력 불확실성

정확한 시·분을 입력해도 초는 미입력이므로 해당 분의 시작과 마지막 밀리초를 계산한다. 범위 입력은 포함된 모든 분의 시작·끝, 범위 내부 절입 순간의 양쪽을 비교한다. 시간 미상은 해당 날 00:00~23:59를 비교한다. 동일한 네 기둥 조합을 묶어 후보를 만들고, 모든 후보에서 같은 기둥만 공통값으로 표시한다. 같은 후보의 첫·마지막 표본은 연속 유효 구간을 의미하지 않는다.

표본 사이의 임계점이 극히 짧게 중첩되는 경우를 수학적으로 전부 포괄하는 구간 증명은 아직 없다. 범위 밖 오차는 반영하지 않는다. 추가로 절입 계산 시각 전후 30분과 입력 범위가 겹치면 월주를 미확정 처리하고, 입춘이면 연주도 미확정 처리한다. 대운 시작도 보류한다. 30분은 검토 정책이며 실측 오차 상한이 아니다.

시간 근거와 오차 범위를 구분한다. '출생기록'이라고 100% 정확하다고 표시하지 않는다. 시간 미상은 시주를 항상 미확정으로 표시하며, 23시 기준이나 경도 보정으로 일주가 달라지는 경우도 반영한다.

## 6. 대운

명시적으로 선택한 기본 전통 규칙: 연간 양+남 / 음+여 순행, 나머지 역행. 월주 다음 또는 이전 간지부터 시작한다. 순행은 다음 12절, 역행은 직전 12절까지의 절대 시간 간격을 이용한다.

`시작 나이(년) = 절입 간격(일) ÷ 3`

`대운 시작 시각 = 출생 시각 + 시작 나이 × 365.2425일`

이후 각 대운을 10×365.2425일 간격으로 계산한다. 이는 일정 길이의 연속 환산이며 달력의 연·월·일을 더하는 방법과 다르다. UI에서 약 나이와 검토값임을 표시한다. 분 미만 출생 오차·절기 오차도 대운 시작일을 움직이므로 표시된 시작일을 확정 사실로 안내하지 않는다.

시간 범위·미상·서머타임 중복·절입 확인 구간 또는 성별 미지정은 대운 계산을 보류한다. 해당 입력에서 대운 시작의 범위를 정밀 산정하는 기능은 후속 과제로 남긴다.

## 7. 기간 조회

연간은 양력 01-01~다음 해 01-01, 월간은 월 1일~다음 달 1일, 일간은 선택 날짜의 00:00~다음 날 00:00를 국내 표준시로 설정한다. 끝 경계는 제외한다. 출생일이 조회 구간 안이면 출생 시각 이후로 제한하고 출생 이전 기간은 거절한다.

12절·대운 변경에서 구간을 나눈다. 일간은 선택한 일주·경도 기준의 날짜 변경에서도 나눈다. 연간 대표 관계는 해당 구간 연간, 월간은 월간, 일간은 일간을 출생 일간과 비교한다. 연간·월간 표의 일주는 그 구간의 임의 대표 순간 계산이므로 해당 구간 전체의 일진으로 사용하지 않는다.

## 8. 기초 해석 및 우선순위

- TG-1: 일간과 대상 천간의 오행 생극·음양 관계로 십성을 정한다.
- E-1: 표시 가능한 천간과 지지 본기 각각 1개씩만 표면 오행을 센다. 계절·통근·지장간 가중치·신강약 점수가 아니다.
- REL-HAP-1 / REL-CHUNG-1 / REL-REPEAT-1: 출생 일지와 조회 지지의 육합·충·동일 관계를 기계적으로 판별한다. 합화 성립과 사건·길흉은 추정하지 않는다.
- HIDDEN-1: 정적 지장간 목록을 제공하며 분일용사 등 학파별 가중치를 적용하지 않는다.

우선순위는 `입력 유효성 → 미확정/확인 구간 → 계산값 → 기초 관계 → 검토용 문장`이다. 일간이 미확정이면 개인별 십성 해석을 보류한다. 상충하는 관계를 종합하여 임의의 길흉 결론을 만들지 않는다.

기본 설명문은 개발자가 작성한 검토용 문장이다. 검수된 고전·전문가 해석 원문을 확보했다고 주장하지 않는다. 생성형 AI API는 호출하지 않는다. 이후 AI 연동 시 확정 JSON·승인된 해석 근거만 입력하고, 계산값 변경·근거 없는 사건 확정을 검출해야 한다.

## 10. v0.2.0 입력·설명 계층 확장

만세력 계산 엔진·절기표는 기존 버전을 유지합니다. `time-input.js`가 조자~야자 시간 선택을 같은 날의 분 단위 범위로 변환하며, 명칭으로 시주를 확정하지 않습니다. `reading-rules.js`는 기존 계산값을 사용해 원국 십성 군·기간 배경·조회 지지 본기·출생 지지 관계·활성 대운을 문장에 연결합니다. 기본 해석에 더하는 조건과 표시 우선순위는 `INTERPRETATION_RULES.md`를 따릅니다. 기본 계산 JSON의 `interpretationStatus`는 엔진 범위의 설명이고, 확장 해석 버전·근거는 `plainReading`에 별도로 포함됩니다.
